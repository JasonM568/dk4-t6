## 已修（本輪）

### open redirect（4 處，反斜線繞過）
舊白名單 `startsWith("/") && !startsWith("//")`（等價 regex `^\/(?!\/)`）擋得住 `//evil.com`，
**擋不住 `/\evil.com`**——WHATWG URL parser 把反斜線正規化成斜線後 `new URL("/\\evil.com", base)`
直接跳 `https://evil.com/`（已 node 實測）。新增 `src/lib/safe-redirect.ts` 的 `safeNextPath()`
雙重防線（regex 擋反斜線 + URL 解析驗 origin），四處統一改用：
- `src/app/auth/confirm/route.ts`（recovery 落點）
- `src/app/(auth)/complete-profile/page.tsx`
- `src/actions/auth.ts`（completeProfileAction redirect）
- `src/lib/member-profile.ts`（requireCompleteProfile 帶 next）
回歸測試：`npx tsx scripts/test-safe-redirect.ts`（19 向量全過）。

### ECPay notify 冪等分岔（1-A）
`ecpay/notify/route.ts` 自帶一份 inline 結算，冪等只認 `status === "PAID"`，沒涵蓋
`CONFIRMED/COMPLETED/REFUNDED/CANCELLED`。管理員把單標成已確認後，ECPay 重送通知會
**二次累加 `totalSpent`、灌水升等**，甚至把已取消/已退款單翻回 PAID。改為委派
`settle.ts` 的 `settlePaidOrder`/`settleFailedOrder`（與 PAYUNi route 同一份，`SETTLED_STATUSES`
一致），商店代號比對留在 route。ECPay 目前僅 sandbox（正式是 PAYUNi），風險低。

### checkoutKey 被「待確認」永久鎖死（1-C）
`updateOrderStatusAction` 原本只有轉 `CANCELLED` 才清 `checkoutKey`。標成
`AWAITING_CONFIRM` 後 `userId:courseId` 唯一鍵永不釋放（lazy expire 只掃 PENDING），
該學員之後對這門課結帳一律撞 P2002，且錯誤訊息「2 小時後自動失效」是假的。
改為「離開 PENDING 一律清 checkoutKey」。

### 課程排序 read-modify-write 競態（3c/3d/3e）
`pinCourseToTop` / `reorderCoursesAction` / `duplicateCourse` 三條都是「交易外讀 →
算 → 非同交易寫」，兩管理員同時排序後寫者用過期快照靜默覆蓋前者。新增
`reorderCoursesInTx(buildOrder)`：讀＋算＋寫全收進單一 `Serializable` transaction
（比照既有已修的 `moveCourse`），並把拖曳排序的名單一致性檢查移進交易內（關掉 TOCTOU）。

### computeDiscount 未 clamp（2-C，硬化）
`src/lib/membership/tier.ts` 的 `computeDiscount` 加 `0–100` 夾擠。DB `discountPercent`
無 CHECK 約束，被設 >100 會讓 total 變負。合法 0–100 值行為不變。

### 1-B 重複付款防護（選「只加結算防護」）
`settlePaidOrder` 金額比對後、寫 PAID 前加防護：查該會員是否已有「同課、非本單、仍
有效已付款（PAID/CONFIRMED/COMPLETED，排除 REFUNDED/CANCELLED）」的訂單。有就拒絕
結算、不重複開通/累計，把 `_duplicatePaymentOf`/`_needsRefund` 標記寫進 Payment.rawCallback
留痕，並 console.error 告警。退款無法自動化（PAYUNi 後台人工），故第二筆一律「擋下＋
記錄待人工退款＋告警」。新增 SettleResult reason `DUPLICATE_PAID`，兩個 notify route
既有的 `!settled.ok` 分支自動接住。**未動過期窗口與 provider 建單參數**（依決定範圍）。

### 1b 自助改密碼——程式層硬化（選「只做程式層硬化」）
`reset-password/page.tsx` 移除自己吃 `?code=`/`#access_token` 塞 session 的相容碼
（session fixation 面），只信任 `/auth/confirm` 用 token_hash 在 server 端建好的 session
（直接 getSession）。已驗證 course 站 recovery 一律走 `/auth/confirm`（forgotPasswordAction
的 redirectTo），舊格式相容碼未被現行流程使用、可安全移除。**未碰 Supabase「重新驗證」
開關**（兩站共用，依決定不動）。

### 2-B 免費課 price=0——admin 擋上架（選「admin 擋 price=0」）
課程表單 schema 加跨欄位 refine：**非專區課（groupId=null）的優惠價不能是 0**，訊息
「免費課請用專區或後台手動開通」。專區課（groupId 有值）不走購買鈕，不受此限、仍可 0 元。
